About

This site is the official user documentation for the Medical Prescription Attachment for WooCommerce plugin, published and maintained by Webkul Software.

About the plugin

Medical Prescription Attachment for WooCommerce is a WordPress plugin that turns a standard WooCommerce store into a compliant online pharmacy. It lets a store owner mark individual products, or whole categories, as requiring a doctor's prescription. Customers buying those products must attach a prescription file before checkout will complete; the order is then held until a store administrator has reviewed the upload and approved or rejected it.

Around that core gate the plugin adds the workflow a real pharmacy needs: configurable upload rules (file formats, file counts, multiple uploads), an Attach Later flow for logged-in customers who do not have the document to hand, a re-upload path after a rejection, four prescription statuses with an order-note audit trail, and three WooCommerce emails that keep the administrator and the customer informed. Version 1.3.x adds optional OCR and AI reading of uploaded prescriptions — including a Google Gemini Vision fallback for handwriting — plus a customer-facing prescription vault, a chronic-disease pill organizer, and a frontend prescription search.

The plugin is sold on CodeCanyon and a working live demo is available, stocked with prescription-gated medicines alongside freely purchasable items so both paths can be tried.

About this documentation

These guides cover installation, configuration, the customer experience, and the store owner's review workflow. They are written for pharmacy and healthcare store operators setting the plugin up, and for developers integrating it into an existing WooCommerce site.

These pages document software behaviour only. They are not medical, pharmaceutical, or legal advice. Deciding which medicines may be sold online, what constitutes a valid prescription, who may verify one, and how long records must be kept is governed by the law of your jurisdiction and remains the responsibility of the store operator.

The documentation is a static site. Every page is also published as raw markdown for AI agents and automated tools — append .md to any page URL, or start from llms.txt.
