Mobile / Scanner Endpoint

Besides the admin console, the extension registers a set of front-end routes under /scanner/. They serve a separate, mobile-shaped scanning app called QuickScan, designed to run inside a Hotwire / Turbo Native mobile application shell.

This page explains what it is, how it behaves, and what each screen does.

Important

/scanner/ is not usable from an ordinary desktop or mobile browser. Chrome, Safari, Firefox and Edge are all redirected to your store's My account page, because the extension serves these routes only to a native app shell. If you open /scanner/ and land on My account, that is the expected behaviour, not a fault. Every screenshot on this page was captured from the app shell, which is why they are phone-shaped.

Who can reach it

RequirementBehaviour if not met
Signed in to WordPress, with either the Manage WooCommerce capability or the Delivery Agent roleA sign-in screen is shown instead of the app
Opened from a Turbo Native or Hotwire Native app shellThe request is redirected to My account
Permalinks set to anything other than PlainThe /scanner/ URLs return a 404

The screens

Home

The landing screen greets the signed-in user and puts a single search box at the top. Below it are counts of your products and orders, and a Recent Activity list of the last few items the app resolved, each with its status.

Anything scanned or searched here is matched against product ID, SKU, the global unique identifier (GTIN/UPC/EAN/ISBN) and the product name, then against the order ID — the same idea as the admin console, and it takes you straight to the matching detail screen.

Products

/scanner/product/ lists your catalogue with a search box, and shows each product's image, name, SKU, price (with the sale price when there is one) and an In Stock or Out of Stock badge.

Scanning a variable product's parent barcode opens this list filtered to the scanned value, so the operator can pick the right variation.

Product detail

Tapping a product — or scanning a simple product or a variation — opens its detail screen on the Details tab: image, name, price, ID, description, and a Product Information panel with the SKU, category, featured flag, tax status and shipping class.

The Inventory tab is the editable half: a Track Stock switch, the available stock with a stepper, and the regular and sale prices, saved with Save Inventory.

Note

Unlike the admin console's Inventory tab, this screen has an explicit Track Stock switch, so it does not force stock management on. See Inventory Management for the console's behaviour.

Orders

/scanner/order/ lists orders with the customer, item count, date, status and total. /scanner/order/<id>/ opens one order: its status selector, the customer, the billing and shipping addresses, the line items with quantities and totals, and the order total with a View Details breakdown.

Scanning the same order again advances it one fulfilment stage, using the same chain, tracking-code requirement and confirmation described in Order Status.

Scan history

/scanner/history/ lists everything this app has resolved, newest first, with the item, its identifier, the timestamp and the status at the time.

Settings

/scanner/settings/ shows the signed-in account and a Log Out action that ends the scanner session.

How it relates to the admin console

They are separate tools reading the same WooCommerce data:

Admin console/scanner/ endpoint
WhereWebkul WC Addons → Smart Barcode ScanFront end, native app shell only
WhoUsers who can manage WooCommerceThe same, plus the Delivery Agent role
Scan historyActivity Logs tabIts own separate history at /scanner/history/
Stock editingInventory tab (always enables stock management)Inventory tab with a Track Stock switch
Create OrderYesNo
Order QR labelsYes, from the WooCommerce order listNo

Because the two keep separate histories, a scan made in the mobile app does not appear in the console's Activity Logs, and vice versa.

The Delivery Agent role

Activating the extension adds a Delivery Agent role to WordPress. It is a deliberately restricted account for couriers:

  • It can sign in to /scanner/ but not to the admin console.
  • It can only work with orders that are already Shipped.
  • It can only move an order from Shipped to Completed, and only after entering the correct verification code for that order.

Assign it from Users → Add New (or Users → Edit User) by choosing Delivery Agent in the Role dropdown. There is no separate settings screen for it.

This is why the console asks "Are you sure you want to change the status without OTP?" when an administrator closes a Shipped order by hand — see Order Status.

Troubleshooting the endpoint

SymptomCauseFix
/scanner/ redirects to My accountOpened in a normal browserExpected. Use the native app shell, or use the admin console
/scanner/ returns a 404Permalinks are set to Plain, or the rewrite rules are staleSettings → Permalinks, choose any non-plain structure and save
A sign-in screen appears in the appNot signed in, or the account has neither Manage WooCommerce nor Delivery AgentSign in with an account that has one of them
